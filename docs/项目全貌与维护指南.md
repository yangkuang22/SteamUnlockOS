# 1. 项目目标与成果

## 目标

在 **SteamOS（Linux）** 上实现与 Windows 版 SteamUnlock/SteamTools 等效的能力：
**输入游戏 ID → 入库 → Steam 自动下载 → 可玩**。

## 已达成

| 能力 | 状态 | 验证方式 |
|---|---|---|
| 未授权游戏管理 | ✅ | 多个游戏实测 |
| 自动下载（含 7.7 GB 大游戏） | ✅ | 满速 94 Mbps 下载完成 |
| 批量入库全部 DLC | ✅ | 253 个 DLC 实测通过 |
| 图形前端（AppID 输入） | ✅ | Web UI 127.0.0.1:8917 |
| 游戏模式生效 | ✅ | `-steamdeck` 进程验证注入 |
| 已入库列表展示 | ✅ | 含 DLC 数量 + 卸载 |
| 稳定性（0 崩溃） | ✅ | 多轮压力测试 |

## 技术路线选择

```
┌─────────────────────────────────────────────────────────┐
│  数据层（Python，我们自己写）                              │
│    · 三个密钥库 + 清单仓库 + API                         │
│    · 写入 Steam 配置（密钥 / 清单 / Lua）                │
├─────────────────────────────────────────────────────────┤
│  运行时层（SLSsteam-Plus，C++，上游开源 + 我们的补丁）      │
│    · 访问权限模拟 → 库里显示"安装"                          │
│    · 清单版本控制 → 指定下载哪个版本                      │
│    · 密钥 hook → Steam 要密钥时我们提供                   │
├─────────────────────────────────────────────────────────┤
│  注入层（LD_AUDIT，系统机制）                             │
│    · 让 32 位 Steam 客户端加载我们的 .so                  │
└─────────────────────────────────────────────────────────┘
```

**为什么选 SLSsteam-Plus 而不是自己写运行时**：
- 它是 Linux 上**唯一**实现了 `PlayNotOwnedGames`（未授权游戏管理）的开源方案
- 上游 SLSsteam 明确拒绝支持密钥/清单（issue #112、#35），所以需要 Plus 分支
- 自己写 hook 风险极高（Steam 用大量内联和虚函数，特征码极难维护）

# 3. 核心技术原理

## 3.1 depot 密钥机制（最重要）

**Steam 下载加密内容的流程**：

```
① Steam 要下载 depot 4012811 的内容
② 先要拿到该 depot 的【32 字节 AES-256 解密密钥】
   查找顺序:
     a) 本地 config.vdf 的 Software\Valve\Steam\Depots\<id>\DecryptionKey
     b) 向 Valve 请求（CMsgClientGetDepotDecryptionKey, eMsg 5438）
        → 账号未授权该 app → Valve 返回 Access Denied (eresult=15)
③ 拿到密钥后 → 向 CDN 授权（AuthenticateDepotID）
④ 下载 chunk → AES-256-CBC 解密 → 解压（zstd/LZMA）
```

**我们的做法**：

```
★ 关键发现: Steam 在【启动时】从 config.vdf 预加载所有 depot 密钥
  → 所以把密钥写进去 + 重启 Steam，就不需要"向 Valve 请求"这一步

同时 SLSsteam-Plus 还 hook 了 IClientUser::LoadDepotDecryptionKey
  → 万一 Steam 还是要问，我们直接提供（不需要写文件）
```

**密钥在 config.vdf 里的格式**：

```vdf
"depots"
{
    "4012811"
    {
        "DecryptionKey"		"dae973d4b45757294a7da031a84c01f05666ffc94165b08e734bbdee6085a6b2"
    }
}
```

⚠️ **必须是 64 位 hex（32 字节）**。写错长度 Steam 完全忽略。

## 3.2 清单（manifest）机制

```
每个 depot 的内容由 manifest 描述:
  · manifest 的标识是 gid（64 位数字）
  · manifest 文件命名: <depotid>_<gid>.manifest
  · 放在 Steam/depotcache/

Lua 里用 setManifestid 指定用哪个版本:
  setManifestid(4012811, "4900984998756496132")
    → 锁定这个版本（游戏更新后我们还在旧版）

不写 setManifestid 时:
  → SLSsteam-Plus 会动态向 Valve 要最新版
  → 但会走 RequestCode 路径（曾经导致崩溃，见 §4.2）
```

## 3.3 访问权限模拟

```
SLSsteam-Plus 做三件事:
  ① PlayNotOwnedGames=true → 改写 IClientApps::BIsSubscribedApp
  ② PackageInjection → 往 Steam 的包表注入 appid → 让 Steam 重新评估许可
  ③ AppIds / AdditionalApps 列表 → 告诉它声明哪些 appid
```

**config.toml 关键配置**：

```toml
PlayNotOwnedGames = true       # 核心开关
PackageInjection = true        # 注入包表（让许可生效）
BlockTicketRequests = true     # 拦下发往 Valve 的所有权票据请求
AppIds = [4012810, 602960]     # 要声明的 appid
AdditionalApps = [...]         # 同上（两个都要填）
```

## 3.4 DLC 的特殊性（重要发现）

**实测结论**：`服装/道具类 DLC 没有独立 depot`。

```
抽查怪物猎人崛起的 8 个服装 DLC:
  1753180 - "Bonus Pack: PC Ass..."     → 无独立 depot
  1753181 - "Fox Mask" Hunter ...       → 无独立 depot
  2133120 - "Fluffy Fur Robe"           → 无独立 depot
  ...
  → 全部无独立 depot

含义:
  DLC 的内容【都在本体 depot 里】
  你只是需要一个"拥有标记"来解锁游戏内的使用权限
  → 所以入库 DLC 只需要 addappid(DLC_ID)，不需要密钥！
```

**实现**：

```lua
addappid(1446780)                          -- 本体
addappid(1446781,0,"<64hex>")              -- 本体 depot（要密钥）
setManifestid(1446781,"3750059740519211061")

-- DLC（253 个，不需要密钥）
addappid(1753180)
addappid(1753181)
...
```

**DLC 列表来源**：SteamUnlock API 的 `config.dlcs` 字段。

## 3.5 注入机制（LD_AUDIT）

```
Linux 动态链接器支持 LD_AUDIT 环境变量：
  指定的 .so 会在【每个动态链接的程序】启动时加载

我们用两个库:
  library-inject.so  (25 KB)  → 负责把 SLSsteam.so 注入到正确的地方
  SLSsteam.so       (9.5 MB)  → 实际的 hook 逻辑

限制:
  只有 32 位 Steam 客户端需要注入（ubuntu12_32/steam）
  64 位子进程会报 "wrong ELF class: ELFCLASS32" —— 这是【无害噪声】
```

**⚠️ 注入的三个必改点（否则游戏模式不生效）**：

```
① ~/Desktop/steam.desktop
   原来是符号链接 → /usr/share/applications/steam.desktop（系统版，Exec=/usr/bin/steam）
   改为实体文件，Exec=~/.local/share/SLSsteam/path/steam

② ~/.config/autostart/steam.desktop
   覆盖 /etc/xdg/autostart/steam.desktop（系统开机自启）
   Exec=~/.local/share/SLSsteam/path/steam -silent

③ ~/.config/environment.d/50-steamunlock.conf
   PATH=${HOME}/.local/bin:${PATH}
   让游戏快捷方式里的 `steam steam://rungameid/N` 走我们的包装器

（④ 对 ~/.local/share/Steam/steam.sh 打补丁也有效，但 Steam 每次启动会还原自己）
```

## 3.6 SteamUnlock 的逆向结论（参考）

**已解析**：

```
.o 文件格式（SteamTools 的 stplug-in 插件）:
  · 内容是 RC4 加密的 Lua 文本
  · RC4 密钥 = a1fca1fca1fdfda1fba1faa1fba1fa42414241 (20 字节)
    GBK 解码 = "↑↑↓↓←→←→BABA"（科乐美秘技）
  · 解密后格式:
      addappid(APPID)
      addapptoken(APPID, "<token>")
      addappid(DEPOT, 1, "<96 hex = 48 字节>")
      setManifestid(DEPOT, "<gid>", <size>)
```

**未能解析（已放弃）**：

```
48 字节 → 32 字节 的转换算法

已排除:
  ✗ 窗口切片（48 字节里不含 32 字节真密钥）
  ✗ XOR 固定掩码
  ✗ MD5/SHA/HMAC 各种组合
  ✗ AES-ECB/CBC（各种主密钥候选）
  ✗ base64 / 大整数解释

定位结果:
  ✗ Main.dll（Nuitka 编译的 Python）→ 只是原样转写，无转换
  ✗ Console.dll（.o 加载器）→ 只是 Lua 宿主 + 共享内存传递，无加密代码
  ✗ diversion.dll → 是原版 steamclient64.dll（未修改）
  → 转换发生在 SteamTools 自己的 steamclient 补丁里（我们没有那个文件）

结论: 不需要破它 —— 用 Sudama 库直接拿 32 字节明文密钥
```

**SteamUnlock 的私有数据来源**：

```
从 Claude 的静态分析报告 + 我们的验证:
  · 密钥下载: http://auth1.caigamer.cn/GetAppinfo/<appid>（API 服务器）
  · 密钥上传: http://list.caigamer.cn/PushKey.php（众包收集用户密钥）
  · 版本检查: gitee.com/blanktm/manifest-auto-update（只做版本更新）
  · GitHub 清单仓库: BlankTMing/ManifestAutoUpdate（已删除，有 fork 存活）
```

# 4. 关键问题与解决方案

## 4.1 问题：无密钥的小 depot 阻塞整个下载

**症状**：密钥清单都齐全，点安装报 `内容仍处于加密状态`。

**根因**：

```
Valve 的 appinfo 里有一些"空 depot"（几十字节，无实际内容）
它们的密钥不存在于任何密钥库
Steam 遇到就报: Failed to initialize depot 4506760 (Missing decryption key)
→ 【取消整个更新】，即使其他 700 MB 的内容密钥都齐全
```

**解决**：给这些 depot 写 **32 字节全零的占位密钥**。

```bash
# 工具自动处理（install-mh3 内置）
# 手动方法：
python3 -c "
import re
p='/home/deck/.local/share/Steam/config/config.vdf'
t=open(p,encoding='utf-8',errors='replace').read()
i=t.find('\"depots\"'); j=t.find('{', i)
block='\n\t\t\t\t\t\"4506760\"\n\t\t\t\t\t{\n\t\t\t\t\t\t\"DecryptionKey\"\t\t\"' + '00'*32 + '\"\n\t\t\t\t\t}'
open(p,'w').write(t[:j+1]+block+t[j+1:])
"
```

## 4.2 问题：RequestCode 导致 Steam 崩溃（★ 最关键）

**症状**：点安装 → Steam 崩溃（`/tmp/dumps/crash_*.dmp` + `assert_*.dmp`）。

**根因（两个）**：

```
① 同一 jobid 重复注入
   [15:10:13] RequestCode: drop+fabricate for app=209370 depot=209383 jobid=4086049243978118896
   [15:10:15] RequestCode: injected fabricated response for jobid=4086049243978118896
   [15:10:15] RequestCode: drop+fabricate for app=209370 depot=209378 jobid=4086049243978118896  ← 同一个 jobid！
   [15:10:15] 💥 崩溃

   Steam 会对同一批的多个 depot 复用同一个 jobid_source
   RequestCode 的 g_pending 以 jobid 索引 → 同一个 jobid 出现两次
   → 两次注入针对同一 jobid 的 ServiceMethodResponse → Steam RPC 层崩溃

② depotId == appId 的畸形请求
   [14:39:45] RequestCode: drop+fabricate for app=625960 depot=625960
   [14:39:48] 💥 崩溃
```

**解决**（`src/feats/requestcode.cpp`）：

```cpp
// ① 同一 jobid 只注入一次
std::unordered_set<uint64_t> g_injectedJobIds;
std::mutex g_injectedJobIdMtx;
...
{
    std::lock_guard<std::mutex> lk(g_injectedJobIdMtx);
    if (!g_injectedJobIds.insert(ready.jobId).second)
    {
        g_pLog->debug("RequestCode: jobid=%llu already injected once — skipping duplicate\n", ...);
        return false;
    }
    if (g_injectedJobIds.size() > 4096) g_injectedJobIds.clear();
}

// ② depotId == appId 时交给 CM 处理
if (depotId == appId)
{
    g_pLog->debug("RequestCode: skip malformed depot==app (%u) — pass through to CM\n", appId);
    return false;
}
```

**⚠️ 不要全局禁用 RequestCode**（我犯过的错）：

```
禁用后:
  捆绑了清单的游戏 → 不需要请求码 → 能下 ✓
  没捆绑清单的游戏 → 需要请求码 → 拿不到 → "No connection" ✗
    [15:08:46] BYldDepotManifest: Failed to get manifest request code, 'Access Denied'
    [15:08:46] AppID 209370 update canceled : Failed downloading 5 manifests
```

## 4.3 问题：游戏模式/桌面图标启动时注入失效（★ 最容易漏）

**症状**：入库成功，重启 Steam 后游戏显示"购买"。

**根因（三层原因）**：

```
① ~/Desktop/steam.desktop 是符号链接 → /usr/share/applications/steam.desktop
   Exec=/usr/bin/steam  ← 直连系统二进制
   （改 ~/.local/share/applications/steam.desktop 没用！因为桌面指的是另一个）

② /etc/xdg/autostart/steam.desktop → Exec=/usr/bin/steam -silent
   systemd 的 xdg-autostart-generator 从它生成 app-steam@autostart.service

③ 游戏快捷方式 Exec=steam steam://rungameid/N → 走 PATH
   而 PATH 里的 steam = /usr/bin/steam
```

**解决**：见 §3.5 的三个必改点。

## 4.4 问题：坏掉的 ACF 导致"无互联网连接"

**症状**：Steam 报 `No connection`，所有游戏都下不了。

**根因**：

```
失败的安装留下损坏的 appmanifest_<appid>.acf:
  StateFlags=18（"需更新 + 完整安装" 矛盾状态）
  SizeOnDisk=0
→ Steam 反复重试 → 一直报 "No connection"（误导性错误）
```

**解决**：

```bash
# 删除坏的 ACF
rm ~/.local/share/Steam/steamapps/appmanifest_<appid>.acf
rm -rf ~/.local/share/Steam/steamapps/downloading/<appid>
# 重启 Steam
```

## 4.5 问题：Steam 启动时还原 steam.sh

**症状**：给 `~/.local/share/Steam/steam.sh` 打的补丁过一会儿就没了。

**根因**：Steam 每次启动会重写自己的启动脚本（自我保护）。

**解决**：不要依赖 `steam.sh`（只对当次启动有效），改用 §3.5 的三个入口。

## 4.6 问题：Steam 商店 API 在国内被墙

**症状**：`_steam_name()` 超时，游戏名拿不到。

**解决**：五源回退（见 §2.2）。优先级最高的 `appmanifest` 是本地文件，不会超时。

## 6.2 32 位编译环境（SteamOS 上没有）

**问题**：SteamOS 默认不能编译 32 位代码（缺 `gnu/stubs-32.h`）。

**解决**：从 Arch 仓库提取工具链到 `~/buildtools`（不需要 sudo）。

```bash
# build-slsteam-plus.sh 会自动做这个
# 手动步骤:
mkdir -p ~/buildtools && cd /tmp
for pkg in cmake pkgconf jsoncpp rhash libuv cppdap lib32-glibc openssl curl; do
    # 从 geo.mirror.pkgbuild.com 下载并解压到 ~/buildtools
done
# 包装器
mkdir -p ~/buildtools/wrappers
# 环境脚本 ~/buildenv.sh
```

**关键编译标志**（否则失败）：

```
CXXFLAGS: -m32 -fPIC -D_GLIBCXX_USE_CXX11_ABI=0 -include cstdint -D_GNU_SOURCE
CFLAGS:   -m32 -fPIC -include stdint.h -D_GNU_SOURCE
LDFLAGS:  -lcurl -lssl -lcrypto    # 不用 pkg-config（libidn2 找不到）
```

## 6.3 SLSsteam-Plus 补丁（19 行，3 个文件）

```diff

-LDFLAGS += $(shell pkg-config --libs "libcurl")
+LDFLAGS += -lcurl -lssl -lcrypto
-DCMAKE_CXX_FLAGS="-m32 -fPIC -D_GLIBCXX_USE_CXX11_ABI=0"
+DCMAKE_CXX_FLAGS="-m32 -fPIC -D_GLIBCXX_USE_CXX11_ABI=0 -include cstdint -D_GNU_SOURCE"

# ② res/patterns.toml（4 条特征码标记 optional，防止 Steam 更新后 abort）
 [Patterns.steamclient."CSteamMatchmakingServers::RequestInternetServerList"]

+optional = true
 # ... 另外 3 条同理

# ③ src/feats/requestcode.cpp（崩溃修复，见 §4.2）
```

## 6.4 恢复出厂（完全回滚）

# 8. 故障排查

| 症状 | 原因 | 处理 |
|---|---|---|
| **游戏显示"购买"** | 注入没生效 | `bash scripts/fix-injection.sh status` → 检查三个入口 |
| **点安装报"内容加密"** | 缺 depot 密钥 | 重启 Steam；或用 install-mh3 重新入库 |
| **点安装 Steam 崩溃** | RequestCode（应已修） | 看 `/tmp/dumps/`；重新编译 |
| **报"无互联网连接"** | 坏的 ACF | 删 `steamapps/appmanifest_<id>.acf` |
| **前端打不开** | 服务没启动 | `~/steam-toolkit/start-webui.sh` |
| **搜不到游戏** | 三个库都没有 | 等社区更新；或从 Windows 提取密钥 |
| **Steam 打不开** | 注入库损坏 | `~/.local/bin/steam-noinject` |
| **特征码失配** | Steam 升级了 | `bash scripts/check-after-steam-update.sh --fix` |
| **一直崩溃** | 触发崩溃保护 | `rm ~/.SLSsteam-crash-count` |
| **Frida/ldd 报 ELFCLASS32** | 64 位子进程加载 32 位库 | 无害噪声，忽略 |

**修复**：


## 9.2 游戏更新后

```bash
bash scripts/refresh-games.sh          # 看有没有更新
bash scripts/refresh-games.sh --apply  # 更新 Lua 里的 gid
# → 重启 Steam，Steam 会下载增量
```

**原理**：Lua 里的 `setManifestid` 锁定了版本，更新时需要改 gid。脚本从 ManifestHub3 拿最新的 gid。

**替代方案（未充分测试）**：去掉 `setManifestid` 让 SLSsteam-Plus 动态拿最新版。之前会崩（RequestCode），现在崩溃已修，可能可行 —— 但需要实测。

## 9.3 扩充密钥源

**当前三个源**：

| 源 | 端点 | 条目 |
|---|---|---|
| Sudama | `https://api.993499094.xyz/depotkeys.json` | 239,946 |
| 社区库 | `https://raw.githubusercontent.com/SteamAutoCracks/ManifestHub/main/depotkeys.json` | 288,381 |
| ManifestHub3 | GitHub API（分支模式） | 62,000+ |

**加新源的方法**：

1. 在 `suos/` 下新建模块，实现 `load() -> dict[depot_str, 64hex]`
2. 在 `suos/multisource.py` 的密钥查找链里加上它
3. 优先放在前面（更新的源放前面）

**已验证不可用的源**（避免重复尝试）：

```
✗ patapancakes/exdepot          → 是 Steam2 存储提取工具，非密钥库
✗ api.steamtools.xyz             → 域名不存在
✗ steam.run/api/depotkeys        → 404
✗ manifest.opensteamtool.com     → 403（Cloudflare）
```

## 9.4 搜索不到的游戏怎么办

**根本原因**：密钥是**从拥有游戏的人那里提取的**，谁都造不出来。

```
三条路:
① 等社区更新（通常几天到几周）
② Windows 上用 SteamUnlock 下载 → 用 tools/提取密钥_Windows.ps1 提取密钥
   → 手动写入 SteamOS 的 config.vdf
③ 如果你自己拥有这个游戏 → 密钥本来就在你的 config.vdf 里
```

# 10. 已知限制与未完成事项

## 10.1 限制

| 限制 | 说明 | 影响 |
|---|---|---|
| **密钥覆盖度** | 三个库合计约 24 万条，不是全部游戏 | 极新的/冷门游戏搜不到 |
| **清单版本锁定** | `setManifestid` 锁版本，游戏更新需手动刷新 | 有更新时跑 refresh-games.sh |
| **第三方 DRM 游戏** | 需要真实票据，我们只能提取自己拥有的 | 第三方 DRM 游戏可能无法运行 |
| **前端只在桌面模式** | 游戏模式没有浏览器 | 入库要切桌面模式 |
| **依赖上游** | RequestCode 等逻辑来自 SLSsteam-Plus | Steam 大版本更新可能要等上游适配 |

## 10.2 未完成 / 可改进

| 项目 | 说明 | 难度 |
|---|---|---|
| **自动版本更新** | 去掉 setManifestid 让 SLSsteam 动态拿最新版（需测崩溃） | 低 |
| **游戏模式内入库** | 游戏模式下用 Decky 插件或 steam:// 协议触发 | 中 |
| **搜索游戏名** | 目前只支持 AppID（名字匹配需要索引 + Steam 搜索 API） | 中 |
| **48字节→32字节算法** | 需要拿到 SteamTools 的 steamclient 补丁 | 高（已放弃） |
| **第三方 DRM 票据共享** | 需要有人贡献票据 | 高 |
| **自动检测密钥库更新** | 定期拉取新版本 | 低 |

## 10.3 绝对不能做的事（安全边界）

```bash
# ✗ 不要用 pkill -f 杀 Steam（会杀到自己的 shell）
#   正确做法: 用 /proc/*/exe 精确匹配

# ✗ 不要把 96 字节（192 hex）的值写进 config.vdf
#   Steam 只认 64 hex（32 字节）

# ✗ 不要全局禁用 RequestCode
#   没捆绑清单的游戏会下载失败

# ✗ 不要依赖 steam.sh 补丁（Steam 会还原它）

# ✗ 不要在主力游戏上做实验（用最小/最不重要的游戏）
```
