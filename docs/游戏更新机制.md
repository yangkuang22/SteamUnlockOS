# 游戏更新机制

> 2026-10-03 端到端实测通过（Barotrauma）

## 为什么需要专门的更新机制

```
我们的 Lua 里用 setManifestid 锁定了清单版本:
  setManifestid(602961, "6603750300904719915")   ← 锁死这个版本

后果:
  · Steam 认为"已是最新"→ 不会检查更新
  · Steam 正版的更新通知对我们【没用】（那是给正版 manifest 的）
  · 游戏更新后，我们还是旧版本，也收不到通知

所以必须:
  我们自己从【数据源】拿新清单 → 写进 depotcache → 更新 gid
```

## 密钥会不会变？—— 不会

```
depot 密钥 (DecryptionKey):
  · 是 depot 的属性，不是 manifest 的属性
  · depot 创建后密钥就固定了
  · 游戏更新 / DLC 发布 / 版本迭代 → 密钥永远不变

manifest gid:
  · 是每个版本的标识
  · 更新 → 新 gid

实测证据:
  紫色晶石 625961: afd931e4...  从入库到现在没变过
  绝地求生 553851: 6b40282b...  同上
  GTA5 271591:    baebeede...  同上
  Barotrauma 三个 depot 更新后，密钥一个都没改

→ 所以更新只需改 gid，密钥不动
```

## 完整链路（实测验证）

```
① 拿最新 gid
   GET https://api.steamcmd.net/v1/info/<appid>
   → data.<appid>.depots.<depot>.manifests.public.gid

② 下载新清单（不需要密钥、不需要请求码）
   GET https://manifest.luastools.xyz/m/<depot>/<gid>
   （provider 链：manifest.steam.run / gmrc.wudrm.com / manifest.luastools.xyz）
   → 返回 Steam manifest 格式（magic 0x71F617D0）

③ 写进 depotcache
   ~/.local/share/Steam/depotcache/<depot>_<gid>.manifest

④ 更新 Lua 的 gid（两个目录）
   ~/.config/SLSsteam/lua/<appid>.lua
   ~/.local/share/Steam/config/lua/<appid>.lua

⑤ 重启 Steam → 自动检测 → 下载
   实测日志:
     [22:03:12] AppID 602960 config changed : updated depots 602962
     [22:03:12] state changed : Update Required, Fully Installed
     [22:03:22] update prefetch finished : 24,258,432 bytes to download
   → Steam 【自动开始下载】，不需要额外触发
```

⚠️ **第 ⑤ 步需要重启 Steam**（Lua 只在启动时读）。热重载不生效。

## 三种使用方式

### 手动（命令行）

```bash
cd ~/steam-toolkit

# 检查单个游戏
python3 -m suos.cli update 602960

# 检查所有已入库游戏
python3 -m suos.cli update --all

# 实际更新（下清单 + 改 gid）
python3 -m suos.cli update 602960 --apply
python3 -m suos.cli update --all --apply

# 然后用图形界面或命令行重启 Steam
~/.local/share/SLSsteam/path/steam
```

### 手动（图形界面）

```
打开前端 → 点「检查更新」按钮
  · 有更新 → 按钮变绿显示"N 个有更新" → 点它 → 全部更新
  · 无更新 → 显示"已是最新"

每个游戏的列表项右侧也会显示标记：
  [有更新] 橙色   [最新] 绿色
```

### 自动（开机检测）

```
已启用 systemd user timer:
  steamunlock-updatecheck.timer
    · 登录后 2 分钟跑第一次
    · 之后每 12 小时一次
    · Persistent=true（关机期间错过的会补跑）

它做的事:
  ① 检查所有已入库游戏
  ② 有更新 → 【自动应用】（下新清单 + 改 gid）
  ③ 发桌面通知："N 个游戏有新版本已准备好，重启 Steam 后自动下载"
  ④ 没更新 → 不打扰用户

查看/控制:
  systemctl --user status steamunlock-updatecheck.timer
  systemctl --user list-timers | grep steamunlock
  systemctl --user stop steamunlock-updatecheck.timer      # 停止
  systemctl --user disable steamunlock-updatecheck.timer   # 禁用

手动跑一次:
  bash ~/steam-toolkit/scripts/autocheck-update.sh
```

## 为什么不做"实时监控"

```
真正的实时监控需要:
  · 常驻后台进程（占用资源）
  · 频繁轮询 API（每天几百次）
  · 或者 hook Steam 的更新检查（复杂且易崩）

而 systemd timer 方案:
  · 每 12 小时一次，每次约 20-50 次 API 调用
  · 游戏更新通常是几小时到几天的间隔
  · 12 小时延迟对单机游戏完全可接受
  · 零常驻进程
```

## 备份与回滚

```
每次 apply 前自动备份 Lua 到:
  ~/steam-toolkit/backup/updates/<appid>.lua.<目录名>.bak

回滚:
  cp ~/steam-toolkit/backup/updates/602960.lua.lua.bak \
     ~/.config/SLSsteam/lua/602960.lua
  # 重启 Steam
```

## 已知限制

| 限制 | 说明 |
|---|---|
| **需要重启 Steam** | Lua 只在启动时读，热重载不生效 |
| **依赖 api.steamcmd.net** | 它挂了就查不到最新 gid（可换 Steam Web API） |
| **清单 source 可能滞后** | provider 拿的是镜像，偶尔比 Valve 慢几小时 |
| **只检查有 Lua 的游戏** | 你正版拥有的游戏 Steam 自己会更新，不需要我们管 |
| **不处理新增 DLC** | 游戏发布新 DLC 时需要重新入库一次（带 DLC 选项） |
