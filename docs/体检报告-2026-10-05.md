## 0. 结论先行

### 一句话根因

**Lua 里 `setManifestid` 指定的 `.manifest` 文件如果没有落到 `depotcache/`，这个游戏必定下载失败；而旧版 `install()` 把"清单下载失败"只当成警告、照样报告"入库完成"。**

清单能不能下到，取决于**入库那一刻的网络运气**。失败是**静默的**。

这就是"每次让 AI 修一个游戏，当时能用、下次加新游戏又坏"的真正原因 —— 之前每次修的都是**那一次恰好成功了**，而不是修掉了这个结构性缺陷。

### 症状与根因映射表

| 用户看到的 | Steam 内部发生了什么 | 真机日志证据 |
|---|---|---|
| 入库后游戏出现在库里 | SLSsteam `addappid` 放行所有权 | `LuaLoader: addappid(2859100)` ✅ |
| 点下载 → "无互联网连接" | 本地无清单 → 找 Valve 要 request code → SLSsteam provider 403 | `Failed to get manifest request code, 'Access Denied'` |
| 刷新 → "内容仍处于加密状态" | 任务取消后级联报缺密钥（实际密钥在 config.vdf 里好好的） | `removed from schedule (result Missing decryption key)` |
| 多试几次 → Steam 崩溃 | 下载状态机在"有所有权/无法下载"间反复横跳 → 状态损坏 | 循环日志 → 进程退出 |

### 修复成效

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 清单缺失时的行为 | 静默忽略，报"入库完成" | 判定致命失败，拒绝写入所有权 |
| 清单下载重试 | 0 次（一次失败 = 永久下不动） | 每源 3 次指数退避 |
| 全零占位密钥 | 给所有无密钥 depot 写入 | 仅给无内容的 marker depot |
| 非 64-hex 密钥 | 原样写入（SLSsteam 静默丢弃） | 源头过滤 |
| Lua 格式一致性 | installer.py 用小写 + flag=1 | 全部统一大写 + flag=0 |
| 单元测试 | 86 通过 | 87 通过（新增回归测试） |
| HILLS (2859100) | state=2，下载失败 | 清单补齐 976KB，ok=True |

4. **④ 崩溃**：用户反复点击 → 反复走 ①②③ → Steam 下载状态机损坏 → 进程崩溃退出

## 4. 发现的全部 BUG（8 个）

### 4.1 严重级别定义

| 级别 | 含义 |
|---|---|
| 🔴 致命 | 直接导致用户描述的症状（下不动 / 崩溃） |
| 🟡 严重 | 数据错误或功能缺失，但不一定每次触发 |
| 🟢 加固 | 潜在风险，暂未出现问题 |

### BUG 1 🔴 清单下载失败不阻止入库（核心凶手）

**位置**: `webui_core.py` install() 流程 §4.9 → §6

**表现**: install() 在清单全部下载失败后仅调用 `warn()`，然后继续写 Lua、写 config.toml 所有权，最终 `res["ok"] = True`，返回 `message = "处理完成，重启 Steam 后即可在库中管理"`。

**后果**: 用户看到"处理完成" → 重启 Steam → 游戏出现在库里 → 点下载 → §2.4 的死亡链（无连接 → 内容加密 → 崩溃）。

**为什么"每次 AI 修完当时那个游戏能用、下次又坏"**: 清单能不能下到，取决于入库那一刻的网络状态。AI 修的是当时恰好成功的那个游戏的其他参数，下次换游戏时如果清单下载碰上网络抖动，照样静默失败。

**本次修复**: ✅ 修复 1（§5.1）

### BUG 2 🔴 清单下载零重试

**位置**: `suos/manifests.py` fetch_manifest()

**表现**: 每个 provider 只试一次，超时即换下一个，全失败返回 `None`。

**后果**: §2.6 证明同一个清单在入库时（13:41）拿不到，4 分钟后（13:45 手动测试）一次就拿到了。国内网络抖动时单次请求极易超时 → 一次抖动 = 游戏永久下不动。

**额外问题**: 把实测一律 403 的 `opensteamtool` 排在第一位，实测唯一稳定的 `luastools` 排第二。

**本次修复**: ✅ 修复 2（§5.2）

### BUG 3 🔴 全零占位密钥导致解密失败 + 潜在崩溃

**位置**: `webui_core.py` _depots_needing_placeholder() / `installer2.py:93`

**表现**: 给所有"无密钥 depot"写 `"00" * 32`（32 字节全零）占位密钥。

**原始意图**: 防止 Steam 遇到 `Missing decryption key` 时取消整个下载任务。

**实际后果**:
- Steam 拿到全零密钥 → 认为"有密钥" → 尝试用全零 AES 解密 depot 内容 → 得到垃圾数据
- 对于几十字节的 marker depot（无实际加密内容）：无害
- 对于有真实清单/内容的 depot：AES 解出垃圾 → 完整性校验失败 → 下载损坏甚至 Steam 崩溃
- 比没有密钥更糟 —— 没有密钥时 Steam 会跳过该 depot 只报错，有错误密钥时会尝试解密然后在垃圾数据上失败

**本次修复**: ✅ 修复 3（§5.3）

### BUG 4 🟡 MH3 密钥长度无校验

**位置**: `suos/manifesthub3.py:93`

**表现**:

```python
for m in re.finditer(r'"(\d+)"\s*\{\s*"DecryptionKey"\s*"([0-9a-fA-F]+)"', out["key_vdf"]):
    out["keys"][int(m.group(1))] = m.group(2)
```

不检查密钥长度。如果 MH3 的 key.vdf 里存的是 96 字节的服务端格式（192 hex 字符），这个密钥会被原样写进 config.vdf。

**后果**: SLSsteam 二进制实证 `addappid(...): invalid key (need 64 hex chars), ignoring` —— 非 64 位的密钥会被**静默丢弃**，但让人误以为"有密钥"。用户看到工具报告密钥写入成功，实际 SLSsteam 根本没用它。

**本次修复**: ✅ 修复 4（§5.4）

### BUG 5 🟡 installer.py 的 Lua 格式不一致

**位置**: `suos/installer.py:119` (setManifestid 大小写)、`suos/installer.py:112` (addappid 第二参数)

**setManifestid 大小写问题**:

```python
# installer.py 生成的是小写 m：
lines.append(f'setmanifestid({d.depotid}, "{gid}")')

# 但 updater.py 和 depotcache_clean.py 都按大写 M 正则匹配：

```

Lua 本身能被 SLSsteam 接受（大小写都认），但 `updater.py` 和 `depotcache_clean.py` 都按大写 `setManifestid` 搜索 → 从这个路径安装的游戏对"更新检查"和"清理白名单"隐形 → 清单会被当垃圾误删。

**addappid 第二参数问题**: installer.py 用 `1`，webui_core.py 用 `0`，真机验证 `0` 是可用的（SLSsteam 忽略此参数）。不影响功能但造成格式不一致。

**本次修复**: ✅ 修复 5（§5.5）

#### 重试逻辑

```python
def fetch_manifest(appid, depotid, gid, *, timeout=60, retries=3, backoff=1.5):
    errors = []
    for name, url in provider_urls(appid, depotid, gid):
        for attempt in range(1, retries + 1):
            try:
                # ... HTTP 请求 ...
            except urllib.error.HTTPError as exc:
                errors.append(f"{name}: HTTP {exc.code}")
                break       # 403/404 是确定性拒绝，重试同源没意义
            except Exception as exc:
                errors.append(f"{name}: {type(exc).__name__}(试{attempt}/{retries})")
                if attempt < retries:
                    time.sleep(backoff * attempt)    # 指数退避: 1.5s → 3.0s
                continue    # 超时/连接失败 —— 值得重试
            if is_steam_manifest(data):
                return ManifestResult(data=data, provider=name, url=url)
            errors.append(f"{name}: 不是有效清单...")
            break           # 有响应但不是清单，换下一个源
```

**重试策略的分辨力（刻意设计）**:

| 失败类型 | 处理 | 理由 |
|---|---|---|
| 超时 / 连接失败 | **重试**（指数退避） | 瞬时问题，§2.6 证明重试有效 |
| HTTP 403 / 404 | **立即换源** | 确定性拒绝，重试同一个源浪费时间 |
| 响应不是清单 | **立即换源** | 数据源端问题，重试不会变好 |
