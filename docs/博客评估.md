# 博客评估：《Steam入库工具原理拆解》

原文：https://blog.csdn.net/weixin_33404102/article/details/167007955

## 总体评价

**有价值，但价值不在"原理"（那部分比较泛），而在几个具体的技术线索。**

作者是"使用者+观察者"视角，不是逆向视角。文章描述的机制**大方向对，但细节有很多不准确**，
而且**没有覆盖我们实际卡住的那一层**。

---

## ✅ 有实际价值的 3 个点

### 1. ★ 区域限制处理的具体参数（全新信息）

原文提到：
> 入库工具对付运行锁区，靠的是修改 Steam 的本地配置文件 **`steam.cfg`** 里的
> **`ForceLanguage`** 和 **`LocalIPOverride`** 参数，把客户端本地网络环境伪装成目标区域。

**这是我没有的信息。**如果以后要处理锁区游戏，值得验证：
```bash
# 检查是否存在
ls ~/.local/share/Steam/steam.cfg ~/.steam/steam.cfg 2>/dev/null
# 或从 Steam 自己的字符串里找
strings ~/.local/share/Steam/ubuntu12_32/steamclient.so | grep -iE "ForceLanguage|LocalIPOverride"
```

### 2. ★ 第三方 DRM的真实机制（和我之前推断一致）

原文：
> 第三方 DRM分两类：① **全程在线验证**（入库无用）② **初始激活 + 本地凭据缓存**
> 工具"支持第三方 DRM"的真实含义：**它分享的不是修改补丁，而是正版激活后的本地状态快照**

**这解释了为什么有些 第三方 DRM 游戏入库能玩、有些不能**，也解释了"授权缓存"的存在。
对将来研究有用：**第三方 DRM 游戏的瓶颈不在 depot 密钥，而在 第三方 DRM 凭据**。

### 3. 清单数据的来源结构

| 清单类型 | 数据来源 |
|---|---|
| 基础全量（AppID） | Steam Web API + 扫描 |
| DLC 增补 | SteamDB DLC 页面 |
| 锁区识别 | 区域价格 API |
| 加密标记 | 社区反馈 |

**这和我们用的 ManifestHub3 是同一类东西**，只是我们用的源更好（有 key.vdf）。

## ❌ 不准确或过时的部分

| 原文说法 | 实际情况 |
|---|---|
| "往 `appinfo.vdf` 和 depotcache 写入模拟配置" | **不准确**。`appinfo.vdf` 是 Steam 自己的加密缓存（我们验证过格式）；工具改的是 **内存**（通过注入） |
| "Steam 下载权限检查可以规避（离线模式缓存授权）" | **不准确**。我们实测：下载需要 **32 字节 depot 密钥**，写进 `config.vdf` 或内存注入 |
| "Self-built manifest = 4万款" | 数字夸大。实际社区库 288,381 条 depot，其中 **39% 是空的（无密钥）** |
| "修改 `appinfo.vdf` 打补丁" | 现在的工具（如 SteamUnlock）**不落盘**，是运行时注入 |

**关键差异**：文章认为"改本地文件"，实际上现代工具是"**运行时内存注入 + 服务器拿密钥**"。

## 🔍 文章完全没提到的（我们踩过的坑）

| 我们发现的 | 文章有提吗 |
|---|---|
| **depot 密钥必须写进 `config.vdf`**（Steam 启动时预加载） | ❌ |
| **SteamUnlock 服务端的 96 字节不是密钥** | ❌ |
| **ManifestHub3（62000+ 分支，含 key.vdf）** | ❌ |
| **"空密钥"小 depot 会阻塞整个下载** | ❌ |
| **SLSsteam-Plus 的 4 条特征码会因 Steam 更新失效** | ❌ |
| **清单请求码（Valve 2026-09 之后的强制要求）** | ❌ |

## 📌 对当前项目的具体帮助

### 可以直接用的

1. **把 `ForceLanguage` / `LocalIPOverride` 加进待研究清单**（锁区游戏用）
2. **第三方 DRM 游戏的预期管理**：能下载 ≠ 能玩，第三方 DRM 是另一层

### 不需要做的

- 文章建议的"备份 appcache"——我们的方案不碰那里
- "用小号"——SLSsteam-Plus 是本地注入，不涉及账号密码

### 值得警惕的一点

文章提到"**游戏突然从库里消失**"的原因：
> Steam 服务器下发正版验证指令，客户端发现本地无许可，就把游戏隐藏掉

**这提醒我们**：Steam 的服务器会主动校验。所以：
- 我们写进 `config.vdf` 的密钥是**合法的**（社区提取的），不会因此被发现
- 但**访问权限模拟（SLSsteam 的 AdditionalApps）**可能被服务器识别
- **建议保持离线模式玩解锁的游戏**，降低触发概率（这一点文章是对的）

---

## 结论

**这篇文章对我们帮助有限**（核心机制我们已经搞得更清楚），但有 3 个可提取的线索：

1. ★ `steam.cfg` 的锁区参数（新信息，待验证）
2. ★ 第三方 DRM 的两类机制（确认了我的推断）
3. **服务器的正版校验会导致游戏消失**（风险提示，合理）

**最重要的启示**：文章反映的是"传统入库工具"（改文件）的思路，
而现代工具（SteamUnlock）已经进化到**运行时注入 + 服务器供密钥**，
这也是为什么我们最后选了 **SLSsteam-Plus + ManifestHub3** 这条路——
它更接近现代做法，而不是文章描述的旧思路。

## 🔬 实测验证结果（我实际查了）

### 文章提到的锁区参数：**在现在的 Steam 里不存在**

```bash
# 在 Steam 所有二进制里搜 ForceLanguage / LocalIPOverride
ubuntu12_32/steamclient.so    → 0 处命中
ubuntu12_32/steam             → 0 处命中
```

**结论**：这两个参数**是旧版 Steam 的**，现在的客户端已经移除。
文章这部分**过时了**。

（现在 Steam 里只有 `Region restricted` / `Region Locked` / `Region not supported` 这类错误提示）

### appinfo.vdf：我们确实没动它

```
文件: ~/.local/share/Steam/appcache/appinfo.vdf  (5.3 MB)
头部: 2944560701 0000000080904f0000000000   ← Steam 自己的格式
mtime: 2026-10-03 11:40   ← Steam 自己写的，不是我们
```

**我们的方案完全不碰这个文件** —— 我们只写：
- `config/config.vdf`（密钥）
- `depotcache/*.manifest`（清单）
- `config/lua/*.lua`（Lua 配置）

**文章说的"打补丁改 appinfo.vdf"是旧做法**，现代工具（含我们）都不用。

### depotcache 的作用：文章说对了一半

文章说「depotcache 里预置 Manifest，客户端就认为内容有效」——**这部分对**。
但它漏了最关键的一环：**Manifest 只解决"下什么"，密钥才解决"能不能解密"**。

我们实测的完整链条：
```
Manifest（depotcache/）     → 告诉 Steam 有哪些文件、哪些块
+ 32字节密钥（config.vdf）  → 让 Steam 能解密下载的内容
+ 所有权伪装（SLSsteam）    → 让库里显示"安装"按钮
+ 清单请求码（SLSsteam-Plus）→ Valve 2026-09 后的新要求
= 能下载、能玩
```

**缺任何一个都不行**——这是文章没有覆盖的层次。
