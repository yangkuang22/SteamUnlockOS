# 稳定性与更新说明

## ★ 会不会把系统搞坏？

**不会。** 原因：

```
SLSsteam 的加载方式:
  Steam 启动 → LD_AUDIT 加载我们的 .so → 修补 Steam 内存
    ↓
  它【只影响 Steam 这一个进程】
    ↓
  崩了最坏结果: Steam 打不开（桌面/游戏模式本身不受影响）
                    ↓
              用 ~/.local/bin/steam-noinject 启动即可
```

**系统启动和 Steam 完全独立**：
- 开机进游戏模式：SteamOS 的 gamescope 会话先启动，Steam 是它的子进程
- 即使 Steam 起不来，你也能切到桌面模式（Steam 设置里或 `steamos-session-select`）
- 桌面环境（KDE/gamescope）不依赖 Steam

## 四层防崩溃保护

### 第 1 层：启动器文件检查（最外层）
```bash
[ ! -s "$LIB1" ] || [ ! -s "$LIB2" ] → 回退普通启动
ldd 检测到缺依赖 → 回退普通启动
```

### 第 2 层：崩溃计数自动降级（新增）
```bash
连续 3 次启动失败 → 自动改为【不注入】启动
恢复方法: rm ~/.SLSsteam-crash-count
```

### 第 3 层：SLSsteam 自身的特征码保护
```toml
SafeMode = false          # 改 true 会让它更保守（功能减少）
OnlinePatterns = false    # 改 true 会尝试在线拉新特征码
```

### 第 4 层：无注入安全网（永远可用）
```bash
~/.local/bin/steam-noinject     # 直接调 /usr/bin/steam
/usr/bin/steam-jupiter          # 系统原版，不经过任何包装器
```

## Steam 自动更新后会怎样？

| 情况 | 结果 | 处理 |
|---|---|---|
| 特征码没变 | 一切正常 | 什么都不用做 |
| 特征码变了（常见） | Steam 能开，但游戏显示"购买" | 跑 `bash scripts/check-after-steam-update.sh --fix` |
| 大版本改动 | 同样，功能失效 | 可能要等上游 SLSsteam-Plus 适配 |

**关键：任何情况下 Steam 本身都能启动**（有 4 层保护）。
