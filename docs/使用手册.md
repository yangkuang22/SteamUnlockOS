# Steam Toolkit 使用手册（最终版）

## 一句话
**在 SteamOS 上像 SteamUnlock 一样"入库 → 下载 → 游玩"。**

## 数据源（最终方案）

| 数据 | 来源 | 覆盖 |
|---|---|---|
| **Lua 配置 + 密钥 + 清单 + 元数据** | **ManifestHub3**（`steamtools-games/ManifestHub3`，62,000+ AppID 分支） | 主流大作 100% |
| 备选：depot 列表 + 全版本 gid | SteamUnlock 服务端 | 任意游戏（但无密钥） |
| 运行时机制 | SLSsteam-Plus（我们自己编译修补） | — |

**ManifestHub3 的每个分支含：**
```
<appid>.lua          官方 Lua（addappid + setManifestid，含依赖 depot）
key.vdf              Steam 格式的密钥文件
<appid>.json         元数据（名称、所有版本分支）
<depot>_<gid>.manifest   所有清单文件
```

## 用法（一条命令）

```bash
cd ~/steam-toolkit

# 1. 检查有没有数据
python3 -m suos.cli check-mh3 <appid>

# 2. 一键准备
python3 -m suos.cli install-mh3 <appid>

# 3. 重启 Steam（★ 必须！密钥只在启动时读）
~/.local/share/SLSsteam/path/steam

# 4. 在 Steam 库里搜索游戏 → 点「安装」→ 自动下载
```

**先看看会做什么（不写入）：**
```bash
python3 -m suos.cli install-mh3 <appid> --dry-run
```

## 原理

```
① python3 -m suos.cli install-mh3 <appid>
      ↓
   从 ManifestHub3 拉：官方 Lua + key.vdf + 全部清单
      ↓
   密钥 → ~/.local/share/Steam/config/config.vdf
   清单 → ~/.local/share/Steam/depotcache/
   Lua  → ~/.config/SLSsteam/lua/  +  Steam/config/lua/
      ↓
② 重启 Steam
      ↓
   SLSsteam-Plus: 让库里显示游戏 + 锁清单版本 + 拿请求码
   Steam: 从 config.vdf 读密钥 → 解密 → 下载 → 安装
```

**关键发现**：Steam 启动时会从 `config.vdf` **预加载** depot 密钥，
所以把密钥写进去就行，**不需要任何 hook 注入密钥**。

## 已排除的思路（别重复踩坑）

| 思路 | 结论 |
|---|---|
| SteamUnlock 服务端的 96 字节 | **不是密钥**（400+ 种转换全失败：XOR/哈希/AES/GCM/盐/拼接/反转…） |
| 用 Cheat Engine 从 Steam 内存抓密钥 | 能抓到（二进制 32 字节），但**只有社区已有的那些**，拿不到独占密钥 |
| 解密工具的 `Kernel` / `applist.json` | AES 加密，密钥运行时派生，静态解不开 |
| 用 SteamUnlock 的激活码 | ❌ 设备绑定 + 3 天冷却，且是 Windows exe（Linux 跑不了） |

## ★ 关键坑：无密钥的小 depot 会阻塞整个下载

**症状**：密钥齐全、清单齐全、`config.vdf` 也写对了，但点安装就报
`内容仍处于加密状态` / `Missing decryption key`。

**根因**：某些游戏（尤其带 DLC 的）在 **Valve 的 appinfo** 里有一个
**几十字节的"空 depot"**，它的密钥社区库里没有。Steam 初始化 depot 时
一遇到它就：

```
Failed to initialize depot 4506760, manifest 507222288937827240 (Missing decryption key)
→ Steam 取消【整个更新】← 即使其他 700MB 的内容密钥都齐全
```

**实例**：紫色晶石（625960）的 depot **4506760**（40 字节），就是它卡住的。

**解决**：给它写一个 **32 字节全零的占位密钥**：

```bash
# 工具已自动处理（install-mh3 会为已知的无密钥 depot 写占位）
# 手动处理方法：
python3 -c "
import re
p='/home/deck/.local/share/Steam/config/config.vdf'
t=open(p,encoding='utf-8',errors='replace').read()
i=t.find('\"depots\"'); j=t.find('{', i)
block='\n\t\t\t\t\t\"4506760\"\n\t\t\t\t\t{\n\t\t\t\t\t\t\"DecryptionKey\"\t\t\"' + '00'*32 + '\"\n\t\t\t\t\t}'
open(p,'w').write(t[:j+1]+block+t[j+1:])
print('已写入占位密钥')
"
```

**原理**：Steam 拿到"密钥"后就不再报错，跳过这个空 depot，
继续下载真实内容（其他 depot 的密钥是有效的）。

**实测**：加上占位密钥后，紫色晶石**立刻能下载了**。

## 已知限制

1. **新游戏无数据** —— 社区收录有延迟（命运石之门 RE:BOOT 就是例子）
2. **第三方 DRM 游戏** —— 能下载，启动需额外处理
3. **必须重启 Steam** —— 密钥只在启动时读取
4. **GitHub API 限速** —— 匿名 60 次/小时（每个游戏约 7 次调用，够用 8 个游戏）

## 回滚

```bash
# 无注入模式启动 Steam
~/.local/bin/steam-noinject

# 恢复原始 SLSsteam
cp ~/steam-toolkit/backup/slssteam-orig/config/config.yaml ~/.config/SLSsteam/

# 恢复 config.vdf
cp ~/steam-toolkit/backup/config.vdf.autobak ~/.local/share/Steam/config/config.vdf
```
